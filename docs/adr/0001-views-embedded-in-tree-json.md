# 视图配置内嵌 tree.json（而非独立配置文件）

file-tree 技能引入多视图（子文件树按 id 渲染到多个文档）能力时，视图配置的存放位置有三个候选。决定采用 **tree.json 顶层 `views` 键**：视图是同一份数据的切片投影，其定义本就属于数据，与数据同生命周期。

## Considered Options

- **技能目录内独立文件**（拒绝）：部署升级是"镜像同步 + PROTECTED 排除清单"，排除清单仅含 tree.json 与撤销历史，技能目录内自放文件会被升级清理。采纳此案需同步维护 deploy.py 排除清单、deploy 契约测试、母体 SKILL.md 三处，漏一处即配置丢失——恰是本决策要消灭的风险。
- **技能目录外独立文件**（拒绝）：部署器天然不触碰，但在每个目标仓库根引入技能外新文件，且首次部署无法由部署器初始化。
- **tree.json 顶层键**（采纳）：PROTECTED 已覆盖（零部署改动）；工具的规范化对未知顶层键原样透传，新旧版本混布互不破坏；视图变更与数据变更共用同一撤销栈；跨机迁移单文件带走全部状态；GUI 查看器只读 root/tags/tree 三键，不受影响。

## Consequences

- 视图变更即数据变更：进入 undo/redo，回滚连同全部视图的渲染产物一起恢复。
- 旧版工具读写 tree.json 不会破坏 `views`，但也看不见它——不渲染、不校验、不报错。
- `views` 的 schema 校验依赖 tree.json 的加载校验，无独立的文件级版本号；未来 schema 演进在加载层做结构迁移。
