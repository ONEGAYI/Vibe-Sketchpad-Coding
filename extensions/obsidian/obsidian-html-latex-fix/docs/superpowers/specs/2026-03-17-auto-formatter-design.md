# 自动格式化助手 - 设计规格

> 日期：2026-03-17
> 状态：已批准
> 作者：Claude

## 概述

**功能名称**：自动格式化助手

**目的**：检测并修复 HTML 标签内 LaTeX 公式中的 `<` 和 `>` 符号，防止渲染错误。

**问题背景**：

当用户在 HTML 标签（如 `<div>`, `<span>`）内书写公式时，如果公式包含 `<` 或 `>` 符号，会导致：
- 公式渲染错误
- HTML 解析异常
- Markdown 语法识别失败

---

## 核心规则

| 符号 | 替换为 | 说明 |
|------|--------|------|
| `<` | `\lt` | LaTeX 小于号 |
| `>` | `\gt` | LaTeX 大于号 |

---

## 检测范围

**检测条件**：
- 仅检测 HTML 标签内的公式
- 公式类型：`$...$`（行内）和 `$$...$$`（块级）

**不检测**：
- 普通 Markdown 段落中的公式
- 公式内已转义的符号（如 `\langle`, `\rangle`）
- 已是 `\lt` 或 `\gt` 的符号

---

## 触发时机

| 时机 | 条件 |
|------|------|
| 打开文档 | 文档处于阅读模式 |
| 切换模式 | 从编辑模式切换到阅读模式 |
| 保存文档 | 无论何种模式 |

---

## 检测逻辑

```
1. 扫描源文件，识别 HTML 标签块
   - 匹配 <tag>...</tag> 结构
   - 记录每个 HTML 块的起止位置

2. 在每个 HTML 块内，查找公式
   - 行内公式：$...$（不含 $$）
   - 块级公式：$$...$$

3. 在公式内，检测问题符号
   - 查找 < 和 >
   - 记录：行号、列号、上下文内容
```

## 交互设计

### 主通知弹窗（右下角 Notice）

```
┌──────────────────────────────────────────────────────┐
│ ⚠️ 检测到 3 处公式格式问题                            │
│                                                      │
│ 若不修复，可能导致：公式渲染错误、HTML 解析异常       │
│                                                      │
│  [一键修复]  [查看详情]  [⚙]  [×]                    │
└──────────────────────────────────────────────────────┘
```

**行为**：
- 不自动消失，需用户操作
- `一键修复`：执行替换，显示成功提示
- `查看详情`：打开详情弹窗
- `⚙`：打开设置页面（占位，暂无实际设置）
- `×`：关闭弹窗，不做修改

### 详情弹窗（Modal）

```
┌──────────────────────────────────────────────────────┐
│  公式格式问题详情                              [×]   │
├──────────────────────────────────────────────────────┤
│  共 3 处问题：                                       │
│                                                      │
│  ┌────────────────────────────────────────────────┐ │
│  │ 第 15 行 | <div>$a < b$</div>                  │ │
│  │               ↑ 小于号需替换为 \lt              │ │
│  ├────────────────────────────────────────────────┤ │
│  │ 第 28 行 | <span>$x > y$</span>                │ │
│  │               ↑ 大于号需替换为 \gt              │ │
│  ├────────────────────────────────────────────────┤ │
│  │ 第 42 行 | ...$z < w$...                       │ │
│  │              ↑ 小于号需替换为 \lt              │ │

│                                                      │
│                              [一键修复]  [取消]      │
└──────────────────────────────────────────────────────┘
```

**展示规则**：
- 内容区域可滚动
- 上下文截取：问题符号前后各 20 字符，超出用 `...` 省略
- 鼠标悬停可查看完整行内容

## 技术实现

### 文件结构

```
src/
├── main.ts              # 添加事件监听
├── checker.ts           # 检测逻辑
├── fixer.ts             # 修复逻辑
├── ui/
│   ├── notice-modal.ts  # 右下角通知弹窗
│   └── detail-modal.ts  # 详情弹窗
└── types.ts             # 类型定义
```

### 核心数据结构

```typescript
interface ProblemItem {
  line: number;        // 行号（1-based）
  column: number;      // 列号
  symbol: '<' | '>';   // 问题符号
  replacement: string; // 替换内容
  context: string;     // 上下文（截断后）
  fullLine: string;    // 完整行内容
}
```

### 事件监听

| 事件 | 触发条件 |
|------|----------|
| `onActiveLeafChange` | 切换到阅读模式时检测 |
| `on('file-open')` | 打开文档时（检查是否阅读模式） |
| `on('save')` | 保存时检测 |

### 修复流程

1. 用户点击「一键修复」
2. 遍历 `ProblemItem[]`，按行号倒序替换（避免位置偏移）
3. 调用 `editor.replaceRange()`
4. 显示成功通知：「已修复 N 处问题」

### 撤销支持

- 使用 Editor API 的 `replaceRange()` 方法
- 自动支持 Ctrl+Z / Cmd+Z 撤销

---

## 边界情况

| 情况 | 处理方式 |
|------|----------|
| 文档不在编辑器中打开 | 跳过检测 |
| 公式内已有 `\lt` 或 `\gt` | 跳过 |
| 公式内有 `\<` 或 `\>` 转义 | 跳过 |
| HTML 块内无公式 | 跳过 |
| 检测到 0 个问题 | 不显示弹窗 |
| 用户快速切换文档 | 防抖处理（300ms） |

---

## 错误处理

| 错误 | 处理方式 |
|------|----------|
| 文件读取失败 | 控制台报错，静默跳过 |
| 替换失败 | 控制台报错，显示「修复失败」 |
| 弹窗已存在 | 不重复创建 |
