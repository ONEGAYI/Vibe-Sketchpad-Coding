## ZCode 启动时能力判断

**本节仅适用于 ZCode，保留在全局正文中**。每次对话开始即按运行环境提供的主模型标识确认以下分支，不等待视觉任务出现才加载规则，也不凭截图内容或主观感觉猜测模型能力。

| 主模型 | 读图方式 |
|--------|----------|
| GLM-5.3（不含 GLM-5.3-Flash） | 按本环境约定，主模型不直接读图；视觉内容交给 `image-reader-agent` 子代理处理 |
| GLM-5.3-Flash | 不适用上述无视觉限制，使用实际可用的多模态能力 |
| 其他模型或型号未知 | 按运行环境明确提供的能力判断；未知时不声称已读图，视觉任务到来时先确认可用的识图途径 |

GLM-5.3 的视觉任务包括识图、OCR、截图复刻、依图实现和视觉验收。子代理负责图片观察、必要的裁剪放大、多图比较、参考图检索及视觉规格或偏差清单；主代理据此推理和修改代码。报错或代码截图以逐字转录为主，诊断留给主代理。

仅当子代理派发失败或模型 API 不可用时，才回退至 `mcp__4_5v__analyze_image`，并说明回退原因。该工具名称为历史命名，不据此推断当前模型；其输出若乱码、与上下文明显矛盾或不足以支撑结论，不据此继续作视觉判断。两种途径都不可用时，说明无法核实的图片内容。

**后台执行偏好**：ZCode 派发子代理及运行预计长耗时的命令时，工具支持则优先使用后台模式（如 `run_in_background: true`），避免阻塞对话；不向不支持该参数的工具传入此参数。
